# INT8 GEMM tuning on gfx1151

The C host now selects two M tiles per raster group for the H3 INT8 down
projection at 32,768 or more tokens. At 37,723 tokens, this improves median
kernel throughput from **39.21 to 41.37 TOPS (+5.5%)**, reducing latency from
148.31 to 140.54 ms. The arithmetic, quantization, operand pitch, workgroup tile,
and fused residual epilogue are unchanged. No additional workspace is needed.

| Tokens | Previous group | Selected group | Previous ms | Selected ms | Throughput improvement |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 32,768 | 4 | 2 | 127.533 | 125.674 | 1.5% |
| 37,723 | 4 | 2 | 148.311 | 140.542 | 5.5% |

These are medians of three rounds, reversing candidate order each round.
The 32,768-token run uses 12 measured launches per round; the 37,723-token
confirmation uses 32. Each timing has one warmup. GPU events cover the kernel,
including the residual epilogue, and exclude transfers and allocation. The
metric is `2*M*K*N / kernel_seconds / 1e12` integer operations per second.
The power setting remained `auto`. Full-render performance was not measured.

The selection is deliberately limited to INT8, K=14,336, N=5,376, M>=32,768.
Other shapes and precisions retain their previous grouping. `Gemm` stores the
group used at compilation and uses that same group to calculate the launch
grid, including padding of the final group.

## Correct dimensions and rejected experiments

The dimensions in `host/h3pipe.cpp` are:

| H3 GEMM | K | N |
| --- | ---: | ---: |
| QKV | 5,376 | 21,504 |
| Attention output | 7,168 | 5,376 |
| Gate/up | 5,376 | 28,672 |
| Down | 14,336 | 5,376 |

Older notes incorrectly labeled K=21,504 as the H3 down projection. Initial
screens inherited that label; their apparent larger gains do **not** describe
the current model. Those screens are excluded from the production claim.

For the actual down projection, the initial three-round comparison measured
38.20 / 40.35 / 38.97 TOPS for row groups 1 / 2 / 4. Smaller groups change
which activation and weight rows concurrent workgroups touch. Improved cache
reuse is a hypothesis for the gain; this experiment did not measure cache
counters.

An experimental 128x256 workgroup tile retained eight 64x64 waves and the same
integer dot products. It passed the full-output gate, but measured only
18.20 / 25.75 / 37.39 TOPS at groups 1 / 2 / 4. It used 177 VGPRs versus the
production kernel's 192, with the same 30,720 bytes of LDS and no spills in
either kernel. Lower register usage did not improve throughput. The wider
tile remains an experiment and is not selected by the host.

## Validation and reproduction

The benchmark checks every output for finiteness and compares sampled outputs
against a float64 dot product of identical INT8 operands, followed by the
epilogue. For the in-place residual kernel, it resets the initial residual
before each invocation and accounts for the warmup plus every measured update.
The final run's sampled relative L2 error is 2.55e-7, and the samples are
bit-identical across the two groups. This checks execution of the quantized
dot product, not quantization error against original floating-point weights.

Small gates checked every output at M=257, K=256, with nonzero scales, gates,
initial residuals, and garbage-filled operand padding. The production tile
passed groups 1/2/4 at N=256; the wider tile passed them at N=512. A plain-GEMM
gate also checked padding 0/64/192 and all three groups. CPU host checks cover
the selection and launch coverage for partial row groups. Both host runtime
builds completed successfully.

All retained measurements and discarded-contention records are in
[`gemm-int8-tuning-benchmarks.json`](gemm-int8-tuning-benchmarks.json).
The benchmark waits for an idle GPU/CPU and retries timings when its monitor
observes another GPU compute client. This is not an exclusive GPU reservation;
display work and activity between monitor samples can still affect timings.

```bash
OPENBLAS_NUM_THREADS=4 /home/zach/code/krea2-loom/.venv/bin/python \
  tools/bench_gemm_i8_tuning.py 37723x14336x5376 \
  --stem gemm_i8_resid_256 --groups 2 4 --pads 64 \
  --rounds 3 --repeat 32 --wait-idle --output build/gemm-tuning/reproduce

bash scripts/test_host.sh
bash scripts/build_host.sh
```

The wider experiment is generated by `tools/gen_gemm_i8_wide.py`. Benchmark it
with `--stem gemm_i8wide_resid_256 --tile-m 128 --tile-n 256`. All GPU kernels
in this study are compiled from Loom source.
